# Local setup

## 1. Prerequisites

- Node.js 22 or newer (developed on 24) and npm
- Docker — the Supabase CLI runs Postgres and Auth in containers
- The resort photographs at `../resort photos` (relative to the repo), only needed to regenerate images

## 2. Install

```bash
npm install
```

The Supabase CLI is a dev dependency (`npx supabase …`). Playwright's browser is installed separately when you first run e2e tests:

```bash
npx -w @eden/web playwright install chromium
```

## 3. Start Supabase locally

```bash
npm run db:start
```

This starts a trimmed stack (database, auth, REST gateway). Studio, storage and realtime are disabled in `supabase/config.toml` because the app does not use them; remove the `-x` list in the root `package.json` if you want Studio.

Print the local URLs and keys:

```bash
npm run db:status
```

## 4. Environment variables

Copy `.env.example` to `.env` at the repo root. **Both apps read this one file**: the API through `node --env-file`, Vite through `envDir`. Vite only exposes variables that start with `VITE_` to the browser.

| Variable | Used by | Purpose |
| --- | --- | --- |
| `VITE_API_BASE_URL` | web | API base URL seen by the browser. `/api` in development (Vite proxies to :4000). |
| `VITE_SUPABASE_URL` | web | Supabase project URL — used only for staff sign-in. |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | web | Publishable key (`sb_publishable_…`). Safe to expose; RLS protects data. `VITE_SUPABASE_ANON_KEY` also works. |
| `VITE_SITE_URL` | web | Canonical public URL (SEO tags, sitemap). |
| `PORT` | api | Default 4000. |
| `NODE_ENV` | api | `development` / `production`. |
| `LOG_LEVEL` | api | Optional pino level. |
| `FRONTEND_URL` | api | Comma-separated origins allowed by CORS. Required in production. |
| `PUBLIC_SITE_URL` | api | Public website URL. |
| `TRUST_PROXY` | api | Number of proxies in front of the API (1 behind Nginx) so rate limiting sees real client IPs. |
| `SUPABASE_URL` | api | Supabase project URL. |
| `SUPABASE_SECRET_KEY` | api | **Server-only** secret key (`sb_secret_…`). The legacy `SUPABASE_SERVICE_ROLE_KEY` is accepted as a fallback. Never expose or commit it. |
| `ADMIN_EMAIL_ALLOWLIST` | api | Optional comma-separated emails; when set, only these accounts may use `/api/admin` even if they have a staff profile. |
| `BOOKING_LOOKUP_SECRET` | api | ≥ 32 random characters. Signs guest confirmation links. Changing it invalidates existing links (guests can still look up by reference + phone). |
| `RESEND_API_KEY`, `NOTIFY_FROM_EMAIL` | api | Optional staff email alerts via Resend. Leave blank to disable. |

Generate a secret:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

## 5. Database

```bash
npm run db:reset
```

This applies `supabase/migrations/*` and loads `supabase/seed.sql` (site settings and two **sample** room types) and `supabase/seed.gallery.sql` (the photo gallery rows, generated by `npm run images`).

## 6. First staff account

There is no public sign-up. Create accounts from the command line:

```bash
npm run admin:create -- --email you@example.com --name "Your Name"            # admin
npm run admin:create -- --email desk@example.com --name "Front desk" --role staff
```

The password is prompted for (or read from `ADMIN_PASSWORD`) so it never lands in shell history. Run it again to reset a password.

## 7. Run

```bash
npm run dev
```

- Website: http://localhost:5173
- Admin: http://localhost:5173/admin
- API: http://localhost:4000/api/health

## 8. Tests

```bash
npm run lint && npm run typecheck
npm test            # shared + web unit tests, then API integration tests (needs local Supabase)
npm run test:e2e    # Playwright: booking journey (desktop) + responsiveness (mobile)
```

The API and e2e suites create isolated rooms, users and bookings and remove them afterwards. They abort if `SUPABASE_URL` is not `localhost`/`127.0.0.1` (override with `ALLOW_REMOTE_TEST_DB=1` only for a disposable test project — never production).

## 9. Photographs

```bash
npm run images
```

Reads the originals (read-only), writes AVIF/WebP variants to `apps/web/public/images/resort/`, and regenerates `apps/web/src/content/image-manifest.json` and `supabase/seed.gallery.sql`. Edit `scripts/image-catalog.json` to add, recategorise or describe photos. See [photos.md](photos.md).
